# Contribution Guidelines

## Public repository standard

Do not add personal names, contact details, credentials, local machine paths, private documents, or model files to committed project files. Use synthetic data in examples, tests, and demonstrations.

## Working standard

Keep changes focused on one tracker task. Explain public interfaces, input validation, expected failures, and security limits in the files that implement them. Add or update relevant tests and documentation with each completed feature.

## Review standard

A review should confirm that the feature works as documented, invalid input is handled safely, access stays within approved scope, and status claims match available evidence. Use the tracker definition of done before marking a task complete.
